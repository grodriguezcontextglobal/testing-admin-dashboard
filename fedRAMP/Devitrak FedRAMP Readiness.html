Devitrak & FedRAMP What it would take, what blocks it today, and the road that actually gets there

The program changed more in the last eighteen months than in the decade before it. Most of what you would have read about FedRAMP a year ago is now wrong — including the part everyone quotes about needing a federal agency to sponsor you.

Not yet — and not first

3 eligibility gates failed

Devitrak is blocked at three independent eligibility gates, any one of which is disqualifying on its own. None of them is about how good the security is; they are about paperwork you don't have, a customer you don't have, and where the server runs. No amount of remediation clears them this year.

But this is not a "no." The work that opens the FedRAMP door is almost exactly the work that closes the Bridges PCS deal and every district deal behind it — and one of the cheap steps on that road, GovRAMP, is itself an accepted FedRAMP entry credential. So the sequence is not K-12 versus federal. It is one road, with revenue at the near end and FedRAMP at the far end, and you are not yet standing on it.

The honest framing: the gating question is not "can we afford FedRAMP," it is "is there a single federal dollar at the end of it." Today there isn't — though there is a real federal market worth deciding about deliberately rather than by default.

One thing worth saying plainly, because the rest of this document is a long list of problems: the instinct to start now is correct — it is the target that's wrong. Working the arithmetic forward from zero compliance artifacts with two engineers, the long pole to any serious credential is 18–30 months, and almost none of that is government queue time (FedRAMP's own review clock is roughly 30 days). It is all Devitrak's own readiness work. If anything GovRAMP-gated or federal is plausible in 2028–29, starting now is roughly on schedule. Nobody in this research said "too early" and then did the subtraction.

One thing is time-sensitive right now

RFC-0033 comments close 9 October 2026. It contains Track 2: Expanding 20x to Self-Hosted or Hybrid-Hosted Services — the scheduled opening for gate 3, the one that currently disqualifies your Windows box. Full Phase 4 requirements are expected around 14 October, and a public RFC specifically on managing self-hosted services lands 4 November. Nothing else on this page has a deadline attached; this does.

Before anything else

Eight live exposures that have nothing to do with FedRAMP

These surfaced during the gap analysis. They are active, they affect real student and payment data, and every one is independent of which certification you eventually pursue. Several are worse than anything previously on record.

The production secrets are published and have never been rotated

Mongo Atlas URI, PlanetScale password, the JWT signing seed, Stripe secret key, SendGrid key, Cloudinary secret, AWS secret key and the Twilio auth token are a tracked .env at the tip of remote branch origin/archive/development-2026-03 on a personal GitHub account. All eight were verified byte-identical to the values in the live .env. Rotating the JWT seed alone invalidates every issued token, so this needs a planned window — but it needs one.

02
Four secrets ship inside the public JavaScript bundle
Vite inlines every VITE_* value at build time. VITE_APP_TWILIO_AUTH_TOKEN, VITE_APP_AWS_AUTHORIZER_TOKEN, VITE_APP_HEADER_AUTH_TOKEN and VITE_APP_SECRETE_KEY_ENCRYPT are readable by anyone who opens devtools on admin.devitrak.net.
03
The consent gate is leaking its own bypass token
NODE_ENV is set nowhere — not in .env, not in .env.example — so every NODE_ENV === "production" check is false in production. At mysql/controllers/school.js:214 the raw guardian-consent one-time-code link is returned in the API response body, defeating the hash-only storage that mysql/helpers/consentOtc.js:20 exists to provide. The same missing variable drops the secure flag from session cookies. One-line fix.
04
Every payment record is downloadable without authentication
POST /api/admin/users is mounted bare on origin/main (routes/admin.js:94) and runs StripeTransaction.find(request.body).populate("user") — an empty body returns every payment record, including Stripe clientSecret values.
05
Any S3 object can be minted a download link, including signed consent PDFs
POST /api/document/download/documentUrl (routes/document.js:119) is unauthenticated and takes an attacker-supplied S3 key, returning a presigned GET for any object in the bucket. Executed guardian consent documents live in that bucket.
06
Admin password hashes are served to the browser by design
AdminUser.find(request.body) has no .select("-password"), so the staff endpoint hands every admin's bcrypt hash to the client — and the frontend depends on it, calling compareSync client-side in two places. Fixing the backend alone breaks login; this needs both sides changed together.
07
Anyone on the internet can log out the entire platform
POST /api/admin/invalidate-all-sessions is mounted with optionalJWT, which never rejects, and increments tokenVersion on every AdminUser in every tenant.
08
The audit log is forgeable and publicly readable
POST /api/transactionaudit_log/create-audit takes raw req.body with no auth, so audit records can be fabricated by anyone; GET /api/transactionaudit_log/audit-log is unauthenticated with no filter and no limit, returning a full cross-tenant dump.

Scale, measured rather than estimated: 297 of 510 route definitions (58.2%) carry no authentication middleware on origin/main, counting router-level guards as authenticated. Including the 40 nodeMailer routes whose guard defaults to warn mode — which blocks nothing — the effective unauthenticated surface is roughly 337 of 510, or 66%. The clone serving the local stack is 217 commits behind origin/main and is missing four security middlewares main has, so the running box is worse than these figures.

The blockers

Three gates, all closed

FedRAMP's 2026 rules are published as a machine-readable ruleset. These are rule citations, not interpretation.

1

No qualifying prior certification

FRC-CLA-ASF · Consolidated Rules for 2026

Class A is the entry tier — the one designed for existing commercial products. It requires a completed SOC 2 Type II, a GovRAMP certification, or a prior FedRAMP Rev5/Ready, finished within the previous 12 months. Devitrak has none of the three. ISO 27001 is explicitly not on the list. And the one on-ramp that never required a prior attestation — FedRAMP Ready — went legacy on 28 July 2026.

2

No federal customer, and the Marketplace listing requires one

FRC-APP-MLF · OMB M-24-15

A Marketplace listing must be obtained before you can apply for certification, and an Initial Implementation listing requires a demonstrated government-wide use case: direct use by multiple federal agency customers, or indirect use inside another government-wide service. FedRAMP's scope is cloud services handling federal information on behalf of a federal agency. Bridges PCS is a DC public charter school. There is no federal customer and no federal pipeline, so this fails outright — and no engineering work changes it.

3

Self-hosting routes you to the path you cannot take

Certification type is determined by hosting · closing date known

FedRAMP routes providers who can deploy onto FedRAMP-certified infrastructure to 20x, and providers running their own infrastructure to modernized Rev5. Production is a self-managed Windows Server VM behind IIS. That routes Devitrak to Rev5 — and Rev5 offers only the Agency path, which needs the federal sponsor that gate 2 says you don't have. The two narrow Rev5 Program lanes opened 10 August 2026 ("Lost Sponsor" and "Ready Conversion") each require something you'd have to have had already.

This is the one gate with a scheduled opening. RFC-0033, opened 9 September 2026, includes Track 2: Expanding 20x to Self-Hosted or Hybrid-Hosted Services — and FedRAMP's definition of self-hosted ("machine-based information resources primarily run on physical infrastructure operated by the cloud service provider") describes Devitrak exactly. The published milestones: a public RFC on managing self-hosted services 4 November 2026, provider meetings January 2027, a draft rules RFC 10 February 2027, and final-rule discussions March 2027. The direct-engagement track is limited to providers who already hold Rev5 Class C or D, so Devitrak cannot join it — but the November and February RFCs are open public comment.

Practical consequence: do not re-platform off the Windows box for FedRAMP reasons. Move it for reliability, deploy safety, or because no-backups-and-no-alerting is untenable — those arguments stand on their own. But "we must be on GovCloud to ever be eligible" is now a question with a date on it rather than a settled fact.

One genuine surprise, worth recording because it contradicts the conventional wisdom: the 2026 ruleset contains no requirement to run on FedRAMP-authorized infrastructure. The old Rev5-era language is gone, replaced by a Minimum Assessment Scope model in which non-scope third parties need only be documented with justification and compensating controls. Real 20x packages list Stripe, Twilio and SendGrid as nonCertified third-party resources and are progressing normally. So your commercial vendor stack is a documentation burden, not a blocker. What actually kills the Windows box is the physical and environmental control family in the Rev5 baseline — PE-13 wants fire detection and suppression with an independent energy source — which a machine in an unnamed facility cannot inherit from anyone.

The door nobody mentions

FedRAMP attaches to an agency's use case, not to a vendor

This inverts the whole framing above, and it is the single most useful thing in this research.

FedRAMP publishes six categories of work that fall outside its scope entirely. Two of them describe a shape Devitrak could actually sell in:

  • "Independent Software Vendor (ISV) applications developed and distributed for installation within a single tenant of an infrastructure-as-a-service or platform-as-a-service offering (the host service itself is within the scope of FedRAMP, but independent software is not)."
  • "Information systems that are only used for a single agency's operations, hosted on cloud infrastructure or platform, and are not offered as a shared service or do not operate with a shared responsibility model."

And the governing sentence: "the specific agency use case for adoption is what matters, not the service itself." A single-tenant Devitrak deployment running inside BIE's or DoDEA's own cloud tenancy, operated by them, needs no certification, no Marketplace listing, and no government-wide use case. All three gates disappear — not because you cleared them, but because they never applied.

Supporting evidence, and it is the strongest datapoint in this document: Infinite Campus won the BIE student-information-system recompete at $2.65M. BIE is a federal agency. No FedRAMP certification for Infinite Campus could be found — the Marketplace is a JavaScript application that resists direct search, so treat this as "no evidence found" rather than "confirmed absent." But a federal agency buying multi-million-dollar commercial K-12 SaaS from an apparently uncertified vendor is exactly what this exclusion predicts.

Three caveats, all load-bearing. This is a business-model change, not a compliance shortcut — different product, contract, support model and margin than multi-tenant SaaS. "Outside FedRAMP scope" does not mean unassessed: the agency still runs its own FISMA ATO and pushes its own control requirements down, and Devitrak's current auth posture would not survive that review either. And only the agency can make this determination — it cannot be self-declared.

The action is not to build anything. It is to ask. One email each to BIE's Division of Acquisitions and DoDEA's Procurement Division asking whether a single-tenant deployment in their own tenancy falls outside FedRAMP for their use case. Cost: zero. A yes opens a real product conversation; a no closes the question permanently instead of leaving it to recur every few months.

Your data

There is no cheap tier available to this system

Under FIPS 199 the gap analysis categorizes Devitrak at Moderate — confidentiality Moderate, integrity Moderate, availability Low, taking the high-water mark. The driver is the K-12 data: full name, date of birth, home address, grade and homeroom, a photo URL, a district SIS identifier and named guardian contact details, for a PK3–5 population that is essentially entirely under 13. NIST SP 800-122 escalates identified minors' PII on exactly this basis, and FERPA and COPPA reinforce it.

Two consequences. First, any plan that starts "get listed at Low, it's cheaper" is invalid for this system as built — the old Tailored/LI-SaaS tier excluded systems holding PII beyond login credentials, and you store children's birthdates and photographs. Second, availability being Low is the only thing keeping this off a High categorization, and the current topology — one box, no load balancer, a documented 30–60 second outage on every Windows Update reboot — could not support a Moderate availability rating anyway.

A latent escalation to watch: there is a defined-but-unrouted Stripe connected-account schema holding a government id_number and ssn_last_4. If that is ever wired up, re-run the categorization — full government ID numbers push confidentiality toward High.

Why the attractive number doesn't apply to you

The $90–100k Class A figure is the one worth understanding, because it is the one that would tempt you — and it prices a starting line Devitrak is not standing on. It assumes a company that already holds a SOC 2 Type II, already runs cloud-native on certified infrastructure, and is remediating findings against a fundamentally sound system. Add SOC 2 first. Add an authentication and authorization rebuild for two engineers, which none of these figures include. The real figure for Devitrak today is not $90k, and nobody can quote it honestly until the prerequisites exist.

Set that against the published pricing: Starter $20/month, Business $350/month. Even the most optimistic vendor number is multiples of plausible annual revenue.

Five things you should not be charged for

  • No SSP, SAP or SAR. The rules state plainly that FedRAMP requires no separate Security Assessment Plan or Report for either 20x or Rev5 — they fold into the Security Decision Record. Anyone quoting to author those is selling a retired deliverable.
  • No application fee. FedRAMP will "not request, store, or publish pricing information for cloud services, independent assessors, or advisory services."
  • No FIPS 140-3 validated crypto below Class D. The string doesn't appear in the 2026 rules. What is a MUST for everyone is an inventory of every cryptographic module in use and whether it's CMVP-validated — which Devitrak lacks, and which is cheap to produce.
  • No GovCloud requirement below Class D. AWS US East/West is Certified at Class C; Azure and Google commercial clouds at Class D. The expensive government-cloud migration everyone assumes is only forced at the top tier.
  • No requirement to run on certified infrastructure. Third-party services just need documenting with justification and compensating controls.
Demand

What your buyers actually ask for

K-12 districts do not ask for FedRAMP

Zero of the K-12 majors — PowerSchool, Clever, ClassLink, Instructure/Canvas, Jamf — appear on the FedRAMP Marketplace. What districts actually require is contractual: a signed data privacy agreement on the SDPC National Data Privacy Agreement (v2.2 is current, supporting 222,000+ signed agreements across 13,000+ districts and 35 State Alliances), a security questionnaire derived from HECVAT (CoSN K-12CVAT Lite v4.1), and increasingly a SOC 2 Type II.

For Bridges specifically the binding instrument is DC Code § 38-831.02 (D.C. Law 21-218), which explicitly covers public charter schools. It mandates reasonable security policies, breach notice to the LEA, deletion after termination, and bans sale, targeted advertising and profiling. That is a contract and policy exercise, not a certification — and it is the thing standing between you and the deal.

The competitive tell in your own category

CGI Federal's Sunflower Asset Management Cloud is the entrenched federal incumbent for exactly your function — FedRAMP Certified since November 2023 at Class C, 4.2 million assets across 75+ federal entities, with task orders at DHS ($6.5M), DOJ/ATF, HHS, DOE, DOT and Commerce/NIST. Meanwhile Asset Panda, EZOfficeInventory and Snipe-IT are not on FedRAMP at all — and Asset Panda is pursuing GovRAMP instead. Your direct commercial peers made the same call this assessment recommends.

Federal demand is real — but the reachable part isn't FedRAMP-gated

Two federal school systems buy commercial K-12 SaaS directly. The Bureau of Indian Education runs 169 schools and ~40,000 students, contracts through its own Division of Acquisitions, and awarded Infinite Campus the recompete at $2.65M. DoDEA runs ~160 schools and 66,000+ students with its own Procurement Division, and had a live small-business set-aside IDIQ whose scope names device management. Elsewhere, Peace Corps bought asset-management SaaS at $1.56M and DOI at $214K — non-giants do win these.

Two cautions. There is no dollar threshold that bypasses FedRAMP — neither the $15,000 micro-purchase threshold nor the $350,000 simplified acquisition threshold exempts you. And E-Rate and ESSER funding do not flow FedRAMP down to districts.

The realistic beachhead is narrower and better: 2 CFR 200.313 requires federal grant recipients to take a physical inventory of equipment every two years. Districts, tribal grant schools and Head Start grantees all carry that obligation, and they buy commercially. That is a product positioning worth building collateral around — and it requires no FedRAMP at all.

What an assessor would find

What is genuinely good — and worth copying

The assessment should not read as uniformly negative, because it isn't. The /api/school namespace is the best-engineered surface in the codebase: every route carries validateJWT + checkTokenVersion + requireIndustry("Education") + a member:* permission, a PII-access audit middleware runs across the whole namespace, and FERPA-style export and erase endpoints exist — with shared guardians deliberately preserved during erasure so one student's deletion doesn't damage another's record. Whoever wrote that understood the problem. It is the pattern the rest of the API should be rebuilt toward.

  • The consent one-time-code design is sound — 24 bytes from crypto.randomBytes, persisted only as a SHA-256 hash. The weakness is transport and the NODE_ENV leak, not the token.
  • SQL identifier injection is being actively remediated: four files already use an allowlist or identifier regex. consumer.js and lease.js are the stragglers, following a pattern the team has already written three times.
  • scripts/deploy-node.ps1 is genuinely good operational engineering — it encodes five real production traps in the right order and refuses to start on a half-installed tree.
  • 57 backend test files including security-focused ones; Dependabot across npm, gomod and docker; /health, /ready and /api/metrics.
  • The staged-rollout discipline on security changes — shipping warn mode first, reading a day of real traffic before flipping to enforce — is a mature pattern most teams don't reach for.

The quality exists as artifacts, not as enforced process. That distinction is precisely what an assessment measures — and it is also the cheapest thing on this page to fix.

The road

Sequenced so that every phase pays for itself

Ordered by when the commercial return arrives, not by compliance tidiness. Phases 0–2 are worth doing even if FedRAMP is never mentioned again.

Phase 0 Now · days · ~$0

Stop the bleeding

  • Rotate all eight leaked production secrets; purge origin/archive/development-2026-03.
  • Move the four VITE_* secrets server-side and rebuild the bundle.
  • Set NODE_ENV=production — one line, closes the consent-token leak and the insecure cookie.
  • Add authentication to the five worst routes: admin password update, admin users, the S3 presigner, invalidate-all-sessions, the audit log endpoints.
  • Stop returning password hashes to the browser (backend and frontend together).
Unlocks Ends live exposure of student, guardian and payment data — and makes the existing security whitepaper safe to send to Bridges, which today it is not.
Phase 1 Q4 2026 – Q1 2027 · ~2 quarters

Make the platform assessable

  • Default-deny routing with an explicit public allowlist, replacing per-route opt-in.
  • Reconcile the three authorization systems into one; scope tenancy server-side, not from a client header.
  • Centralized, append-only log shipping off the box with real retention.
  • CI with required review, a dependency gate, and a production box that pulls and never pushes.
  • An actual staging environment, and backups with a tested restore.
  • Answer the two open unknowns: where the box lives, and what app.devitrak.net calls (a day of access logs, not a code read).
Unlocks Survives a district security questionnaire. Hard prerequisite for every phase below — and the single largest engineering investment on this page.
Phase 2 Parallel with 1 · weeks · ~$0

Sign the paperwork districts actually want

  • Execute the SDPC National Data Privacy Agreement — v2.2 is the current standard. A v2.3 finished community review on 15 September 2026, so confirm which version your State Alliance is on before signing.
  • Add DC Code § 38-831.02 terms — security policy, LEA breach notice, deletion on termination, no sale or targeted advertising.
  • Complete a CoSN K-12CVAT Lite v4.1 questionnaire and keep it current.
  • Finish the draft Privacy Policy and Terms of Use sitting in Legal.
Unlocks Bridges PCS, and every district behind it. The cheapest revenue-bearing step on the page, and almost entirely contract work rather than engineering.
Phase 2b Q4 2026 · ~8 weeks · $1,500

Buy the $1,500 independent read

A GovRAMP Single Security Snapshot ($1,000 plus $500 membership) scores you against 40 NIST 800-53 Rev5 and MITRE ATT&CK controls: a one-hour intake, 28 days to upload evidence, about three weeks to a scored maturity letter. Crucially it is confidential unless you choose to publish it, so a bad score carries no external risk.

Unlocks A third-party-scored baseline to plan against instead of inference. Do this regardless of which certification you eventually choose; it is what makes the SOC 2-versus-GovRAMP decision a data question instead of an argument.
Phase 3 2027 · $25–150k + $20–50k/yr

SOC 2 Type II

Requires an observation window over a functioning control environment, which is why it cannot start before Phase 1 lands. The wide cost range reflects genuinely different scopes and auditors — get three quotes.

Unlocks District and enterprise procurement on its own merits — and it is the literal entry ticket for FedRAMP 20x Class A under rule FRC-CLA-ASF. This is the phase where the K-12 road and the federal road become the same road.
Phase 4 2027 · $1.5k–$10.5k per year

GovRAMP

StateRAMP rebranded to GovRAMP in February 2025 — same organization, same fees, now covering state, local, tribal, territorial and educational buyers. It is the framework that actually governs K-12 and SLED sales, and it is the path Asset Panda chose. Fees are revenue-tiered; at Devitrak's scale (under $1M) the ladder is:

TierControlsAnnual fee, under $1M revenue

Two things to read off that table. These are recurring annual fees, not one-time — Core is a $10,500/year commitment including dues, which is a subscription, not a purchase. And Core is the sweet spot: 60 controls, no third-party assessor, no government sponsor. Ready and Authorized have lower PMO fees but add 3PAO costs, and Authorized reintroduces the same sponsor problem FedRAMP has.

Confirm Core's fee before budgeting: the pricing overview says $10,000/year, while GovRAMP's own Core page says a one-time $9,000 plus $250/quarter. Same order of magnitude, different shape.

Unlocks A recognized security badge for SLED and K-12 buyers — and it double-counts, because GovRAMP at any impact level is an accepted qualifying framework for FedRAMP Class A.
Phase 5 2028–29 · conditional

FedRAMP — only on a trigger

Attempt this only if a federal use case has actually materialized. Clearing gate 2 requires a demonstrated government-wide use case. Clearing gate 3 means either re-platforming onto certified infrastructure or waiting for the self-hosted rules RFC-0033 Track 2 is scheduled to produce in 2027 — which is a real reason not to re-platform preemptively.

Class A is the door, not the destination. FedRAMP presumes Class A adequate only for "pilots, configuration and testing, extremely low or negligible risk, public information, minimal users." A federal deployment holding children's names, birthdates and addresses is none of those; an agency would categorize it Moderate, which points at Class C — a 2-week package refresh, at least two automated validation methods per indicator, and six months of persistent validation history. The escalation is forced: 12 months to begin transition once a federal customer is using the service. Class D still requires an agency sponsor; the sponsorless path covers A, B and C only.

Unlocks Federal sales — and statutory reciprocity under 44 U.S.C. § 3613(e), where agencies must presume a FedRAMP package adequate at or below that impact level.
Open questions

Decisions only you three can make

Why do you want FedRAMP?

Every track of this research assumed the goal is federal revenue. It might not be. The plausible alternatives point to completely different answers: a prospect asked for it; an investor or acquirer asked; Fredrik heard the word on a sales call and it became a requirement by telephone; or it is standing in for "our security is bad and we want a forcing function."

Recommendation — answer this before anything else, because it can invalidate everything above. If it's the last one, say so: that is a completely legitimate reason, and the roadmap here delivers the forcing function far more cheaply than FedRAMP would.

Are you already in breach of what you owe Bridges PCS?

DC Code § 38-831.02 binds Devitrak as an "operator" and requires "reasonable security policies and procedures appropriate to the nature of the personally identifiable student information." Devitrak has zero security policies, an unauthenticated admin takeover chain with no audit record, and a consent gate emitting its own bypass token — against a population that is essentially entirely under 13.

Recommendation — this week, before any certification spend. Read the signed Bridges agreement and the marketing security whitepaper against what actually exists. This is the only question on this page with legal consequences already attached, and framing this work as certification planning actively displaces it.

What does app.devitrak.net actually call?

Its source isn't in the workspace. It is the stated reason two security middlewares are stuck shipping in observe-only mode, and it makes an authorization boundary undrawable.

Do we test the federal single-tenant route?

The scope exclusion says a single-tenant deployment inside an agency's own tenancy falls outside FedRAMP entirely. Only the agency can make that determination.

Recommendation — send the email, don't build the product. One each to BIE's Division of Acquisitions and DoDEA's Procurement Division. Cost: zero. A yes opens a real product conversation; a no closes the question for good.

K-12 or AV — the positioning question is still open
